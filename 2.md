# 0. ARQUITECTURA QUE NO DEBES ROMPER

AtlasPOS es un sistema MULTICAJA.

Arquitectura objetivo:

                    ┌─────────────────────┐
                    │   SERVIDOR CENTRAL  │
                    │ AtlasPOS + MySQL    │
                    └──────────┬──────────┘
                               │
              ┌────────────────┼────────────────┐
              │                │                │
          CAJA 01           CAJA 02          CAJA N
       Workstation A     Workstation B     Workstation N

Todas las cajas trabajan contra el servidor central.

Por lo tanto:

- `SERVER` ES un contexto legítimo.
- NO eliminar `SERVER`.
- NO obligar al servidor a registrarse como caja.
- NO convertir el servidor central en una workstation ficticia.
- NO romper operación multicaja.
- NO crear una base de datos por caja.
- NO crear inventarios independientes por caja.
- StoreId identifica la tienda/sucursal.
- TerminalId identifica la caja/workstation.
- UserId identifica al operador.
- varias cajas pueden operar simultáneamente.
- cada caja debe conservar identidad propia.
- caja y servidor NO son el mismo trust context.

El problema a resolver NO es la existencia de `SERVER`.

El problema es impedir que una CAJA CLIENTE pueda obtener privilegios
del contexto SERVER simplemente omitiendo o manipulando TerminalId.
